# Aevric AI — Development Roadmap

This document translates [AEVRIC_VISION.md](AEVRIC_VISION.md) into execution phases. It distinguishes current work from future ambition and does not imply that later-phase systems are already operational.

## Now — Phase 1: Foundation + Real Users

### Objectives

- Keep public Aevric stable.
- Build Control Center V1.
- Measure real usage.
- Preserve advanced Aura architecture.
- Establish canonical intelligence contracts.
- Continue provider and model abstraction.

### Do Not

- Activate RL.
- Rebuild simulation yet.
- Train a foundation model.
- Connect every legacy engine.

Phase 1 should establish operational truth and real-user evidence before expanding the intelligence architecture.

## Phase 2: Decision → Strategy Unification

### Objectives

- Inspect existing strategy implementations.
- Define a canonical Strategy schema.
- Adapt useful existing components behind canonical contracts.
- Connect Decision Intelligence to Strategy.
- Create strategy evaluation.
- Maintain Decision V2 safety and grounding boundaries.

This phase must reconcile existing work rather than introduce another parallel strategy system.

## Phase 3: Simulation V1

Create a controlled simulation architecture representing:

- state
- variables
- actions
- constraints
- assumptions
- transitions
- outcomes
- uncertainty
- multiple scenarios or runs
- strategy comparison

Begin with one narrow, measurable domain. Do not attempt world simulation. Simulation results must distinguish heuristic exploration from calibrated prediction.

## Phase 4: Outcome System

Create first-class outcome records. Where appropriate, authorized, and consented, track:

- the decision made
- the strategy selected
- predicted outcome
- actual outcome
- unexpected changes
- user evaluation
- usefulness

Outcome records should preserve provenance, timing, tenant boundaries, consent, and the conditions under which comparisons remain meaningful.

## Phase 5: Learning V1

Start offline. Use outcomes for:

- decision evaluation
- strategy evaluation
- simulation calibration
- assumption accuracy
- planning effectiveness

There must be no automatic, uncontrolled production self-modification. Learning enters production only through evaluated, observable, reversible, and approved changes.

## Phase 6: Developer Platform

Productize the existing API and platform foundations. Potential work includes:

- developer identity
- API keys
- versioning
- quotas
- usage metering
- webhooks
- SDKs
- documentation
- developer console
- billing

The platform should expose stable canonical capabilities rather than leaking internal architectural generations.

## Phase 7: Enterprise

Strengthen:

- SSO
- RBAC
- audit trails
- governance
- enterprise knowledge
- institutional memory
- organizational decisions
- enterprise simulations
- policies

Enterprise expansion depends on mature tenant isolation, authorization, retention, privacy, security operations, and administrative controls.

## Phase 8: Environment Ecosystem

Develop validated domain environments. Later, allow approved developers to create environments under explicit contracts and validation requirements.

Do not build marketplace economics before simulation quality is proven.

## Phase 9: Specialized Aevric Models

Use Aevric-specific evaluations and consented outcome data to evaluate:

- fine-tuning
- adapters
- distillation
- self-hosting
- specialized Aevric models

Proceed only where benchmarks demonstrate meaningful value over available external or open-weight alternatives.

## Phase 10: Bounded Autonomous Intelligence

Introduce execution only with:

- explicit policies
- authorization
- observability
- human approval where appropriate
- rollback
- auditability
- bounded objectives

Autonomy should advance one measurable level at a time. Safety, authority, and reversibility are architectural requirements.

## Research Horizon

Preserve these strategic research directions without treating them as immediate product commitments:

- autonomous research
- advanced learning and RL
- learned world models
- simulation marketplace
- multi-domain simulation
- world simulation
- deeper proprietary Aevric models
- deeper AI infrastructure

Research systems remain subject to evaluation, privacy, consent, governance, and human validation.

## Current Immediate Build

**CURRENT PHASE:** Phase 1 — Foundation + Real Users

**NEXT IMPLEMENTATION:** Aevric Control Center V1

**AFTER CONTROL CENTER:** Decision → Strategy Unification

## Roadmap Guardrails

- Preserve Decision V2 as the production decision foundation.
- Preserve older Aura systems until deliberate review and classification.
- Prefer canonical contracts over additional parallel engines.
- Measure current capability before representing future capability.
- Introduce outcome collection before learning.
- Introduce evaluation before adaptation.
- Introduce authorization and observability before autonomy.
- Validate narrow simulation environments before ecosystem or marketplace work.
- Increase model ownership only when evidence demonstrates strategic value.
- Keep public Aevric stable while each next step is proven.
